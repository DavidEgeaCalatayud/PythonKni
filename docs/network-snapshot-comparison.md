# Network Intelligence Snapshot Comparison

Network Intelligence can compare two previously exported snapshots without starting discovery, reading the current live inventory or performing any network probe.

The feature is intended to answer a historical question: **what materially changed between two known Network Intelligence states?**

## Supported inputs

The comparison action accepts the existing report formats produced by `Export snapshot report`:

- `.json`: a Network Intelligence report document;
- `.zip`: an evidence bundle containing the fixed `report.json` member.

The ZIP reader does not extract the archive. Only `report.json` is read into memory.

Comparison currently accepts report schema versions 1 and 2. Both reports must describe the same canonical IPv4 CIDR scope.

## Validation and input limits

Saved reports are treated as untrusted input even when they were normally generated by PythonKni.

Before comparison, PythonKni validates:

- supported integer `schema_version`;
- timezone-aware ISO-8601 `generated_at`;
- valid IPv4 CIDR scope;
- unique, non-empty asset identifiers;
- asset IPv4 addresses inside the declared scope;
- TCP/UDP-style port values in the `1..65535` range;
- string service collections;
- unique relationship identities;
- non-empty relationship type/source/target identifiers;
- Network Security Score in the `0..100` range;
- string security findings;
- timeline and summary container shape.

A report payload is limited to 20 MiB. ZIP evidence bundles additionally reject encrypted `report.json` members and suspicious compression ratios. Other archive members are ignored and never extracted.

## Asset identity

Assets are matched by persisted `asset_id`, not by a heuristic combination of IP, hostname or vendor.

This is deliberate. After the identity-reconciliation work in PR #54, a valid MAC is the canonical persistent identity when available. Historical reports that do not contain enough evidence to prove that two different asset IDs represent the same physical device are not heuristically merged during comparison.

A false negative (one removed asset plus one added asset) is safer than incorrectly joining two devices after DHCP address reuse.

## Meaningful asset changes

For an asset present in both reports, comparison detects changes to:

- IP address;
- MAC address;
- hostname;
- vendor;
- device type;
- exposure risk;
- online/offline state;
- classification confidence when present in both schemas;
- opened and closed ports;
- added and removed services.

The following observation metadata does **not** create a changed-asset result by itself:

- `last_seen`;
- `last_change`;
- repeated classification/evidence timestamps.

This prevents a normal rescan from making every device look changed when its effective state is identical.

## Relationship changes

Relationship identity is the tuple:

```text
(kind, source_id, target_id, protocol, source_port, target_port)
```

PythonKni reports relationship additions and removals, plus changes to:

- confidence;
- supporting evidence.

`observed_at` alone is ignored so refreshing the same LLDP/MAC-table evidence does not produce artificial topology churn.

## Security posture changes

The comparison shows:

- Network Security Score before and after;
- signed score delta;
- new findings;
- resolved findings.

The score remains the same deterministic project-defined heuristic used by the live Network Intelligence dashboard. Snapshot comparison does not recalculate old reports with newer rules; it compares the scores stored in each report so the historical artifact remains reproducible.

## User flow

```text
Network Intelligence
        |
        +-- Export snapshot report  ---> baseline.json / baseline.zip
        |
        +-- Export snapshot report  ---> current.json / current.zip
        |
        v
Compare saved snapshots
        |
        +-- bounded offline load
        +-- schema/scope validation
        +-- asset diff
        +-- relationship diff
        +-- security-score/finding diff
        |
        v
Human-readable comparison dialog
```

The comparison action is disabled while a Network Intelligence worker is active, matching the existing report-export behavior.

## Safety and privacy properties

Snapshot comparison is entirely local and read-only:

- no host discovery;
- no port probing;
- no ONVIF, HTTP, RTSP or other network request;
- no credential attempt;
- no external API or vendor lookup;
- no ZIP extraction;
- no mutation of the persistent asset inventory;
- no mutation of relationship or timeline data.

The selected snapshot files are read only for the duration of the comparison and are not imported into the live SQLite inventory.
